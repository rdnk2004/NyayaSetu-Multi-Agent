# NyayaSetu Benchmark Evaluation Dataset & Methodology

This directory houses the labeled evaluation dataset (`labeled_cases.json`) and timestamped output results from end-to-end evaluation runs (`results_<timestamp>.json`).

---

## Dataset Structure (`labeled_cases.json`)

Contains 20 curated real-world legal scenarios under the **Consumer Protection Act, 2019**:
- **14 Clear-cut cases:** Scenarios with unambiguous factual grounding and clearly defined legal remedies/sections.
- **6 Ambiguous / Grey-zone cases:** Genuine competing legal theories (e.g., limitation period accrual, unfair contract clause validity, unidentifiable manufacturer vs seller liability) used to validate the Adversarial Debate Mechanism.

Each case defines:
- `id`: Unique identifier (`case_01` to `case_20`).
- `citizen_message`: Unstructured initial situation narrative provided by the citizen.
- `intake_answers`: Pre-configured factual answers for multi-turn intake questions.
- `specific_legal_question`: The focal legal issue distilled from the intake checklist.
- `expected_cited_sections`: Statutory sections required for citation grounding.
- `case_type`: `"clear_cut"` or `"ambiguous"`.
- `expected_ambiguity_outcome`: For ambiguous cases, expected grey-zone flags and theories.

---

## Evaluation Execution

To run the full evaluation suite against the real Gemini API and ChromaDB:

```bash
python scripts/run_evaluation.py
```

### Metrics Tracked
1. **Citation Grounding & Match Rate:** Percentage of cases where `verified=True` and at least one cited statutory section matches the ground-truth expected set.
2. **Citation Rejection Rate (Hallucination Proxy):** Percentage of citations generated by the QA Agent that were caught and rejected by the Citation Verification Agent.
3. **Grey-Zone Detection Accuracy:** Percentage of ambiguous cases where the Debate Mechanism correctly adjudicates `is_grey_zone=True`.

## Methodological Note: LLM Non-Determinism & Run Variance

> [!IMPORTANT]
> **Do not evaluate code changes based on single-run case-by-case deltas.**

Because NyayaSetu executes multiple LLM calls per case (Query Understanding fact extraction, QA answer generation, Citation Verification auditing, and Debate Mechanism adjudication), individual runs exhibit natural stochastic variance:

1. **Noise in Single-Run Comparisons:** Point-in-time diffs between two single runs can falsely suggest a regression or improvement on specific cases (e.g. `case_13` or `case_18` flipping between pass and fail purely due to slight wording differences in generated answers or audit explanations).
2. **Multi-Run Protocol:** When testing modifications to prompt templates, retrieval parameters, or agent logic:
   - Execute the evaluation **2 to 3 times** on the baseline.
   - Execute **2 to 3 times** on the candidate branch.
   - Compare the aggregate metric distributions and consistent trends rather than an isolated delta on one run.
